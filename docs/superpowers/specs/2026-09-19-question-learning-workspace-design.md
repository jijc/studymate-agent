# StudyMate 知识库学习工作台设计

## 目标

把 `/questions/:libraryId` 从带网站侧边栏的普通详情页改造成沉浸式双栏学习工作台，让用户阅读长答案时始终保留题目目录，并能从常见追问进入完整解析后返回原题。

## 页面边界

- `/questions` 继续使用共享侧边栏，负责浏览、搜索和收藏公共知识库。
- `/questions/:libraryId` 不使用网站侧边栏，改为知识库专用学习工作台。
- 全站 Header、最大宽度、背景、颜色、字体和基础组件保持复用。
- 本轮仍使用静态数据，不接入真实接口；数据访问函数需要保持“目录一次加载、答案按题目 ID 获取”的未来接口边界。

## 桌面端布局

- Header 下方的页面区域固定为浏览器剩余高度，页面主体不整体滚动。
- 顶部使用紧凑知识库工具栏：返回入口、知识库标题、标题后的弱化题目数量和一句简介。
- 工具栏下方为双栏：左侧题目目录约 `352px`，右侧为自适应答案学习区。
- 左右两栏分别拥有独立的 `overflow-y-auto` 滚动容器。
- 切换普通题目时右侧回到顶部；进入追问后返回原题时恢复原题答案区域的滚动位置。

## 移动端布局

- 页面恢复自然纵向滚动，不强制双栏。
- 题目目录通过 Base UI Dialog 侧滑抽屉打开，复用同一个 `QuestionDirectory` 组件。
- 选择题目后关闭抽屉并显示对应答案。

## 题目目录

- 题目使用数据中的稳定 `sequence` 编号，展示为 `001`、`002` 等，不使用过滤结果下标。
- 一次性渲染最多 500 条轻量目录数据，不引入虚拟列表或分页。
- 目录数据只承担编号、标题、章节等导航信息；完整答案由题目 ID 单独获取。
- 搜索只过滤目录显示，不改变题目的原始编号。

## 学习内容层级

答案默认折叠。用户点击“查看完整解析”后，按照以下顺序展示：

1. 关键词解释：用简短、通俗的文字拆解题目术语。
2. 白话理解：先直接回答问题，帮助快速建立直觉。
3. 示例代码：仅在题目有代码时展示，紧跟白话理解。
4. 标准答案：适合正式面试表达的完整回答。
5. 原理解析：解释机制、边界和工程取舍。
6. 常见追问：展示 1–3 个关联题目和一句摘要。
7. 面试表达建议：保留原有面试场景价值，作为紧凑提示区。

## 常见追问

- 追问使用稳定 `questionId` 关联已有题目，不依赖题目位于目录的哪一页。
- 追问卡片展示题目和一行摘要，避免只有标题。
- 点击“查看完整解析”后，右侧切换到追问题目的完整学习内容并自动展开答案。
- 页面显示“返回原题”入口；返回时恢复原题和此前的右侧滚动位置。
- URL 查询参数保存当前题目和来源题目，使浏览器返回键与分享链接具备明确状态。

## 数据模型

- `LibraryQuestion.sequence: number`：知识库内稳定编号。
- `LibraryQuestion.keywords: Array<{term: string; explanation: string}>`：关键词解释。
- `LibraryQuestion.plainAnswer: string`：白话理解。
- `LibraryQuestion.answer: string`：标准答案。
- `LibraryQuestion.followUps: Array<{questionId: string; title: string; summary: string}>`：可跳转追问。
- `getQuestionDirectory(libraryId)` 返回轻量目录数据。
- `getQuestionAnswer(libraryId, questionId)` 按 ID 返回单题完整内容。

## 验收标准

- 详情页不再出现“题库侧边导航”，列表页仍保留共享侧边栏。
- 标题和题目数量处于同一行，不再由数量单独占行。
- 目录显示稳定三位编号，搜索后编号不变化。
- 桌面端左右两栏独立滚动且页面没有横向溢出。
- 展开答案后的内容顺序符合设计，代码位于白话理解之后。
- 点击追问可进入完整解析，并能返回原题。
- 移动端目录通过组件库 Dialog 抽屉呈现。
- 自动化测试、Lint、构建和真实浏览器验收通过。
